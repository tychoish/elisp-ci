A streamlined suite of composite GitHub Actions to execute ERT test suites,
configurable linters, and code coverage analysis for Emacs Lisp packages with
zero configuration boilerplate.

* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=elisp-ci= eliminates repetitive shell boilerplate from Emacs package CI
workflows by encapsulating:

- *Automatic Dependency Discovery*: Automatically scans =Package-Requires=
  headers across package =*.el= source files and installs required ELPA
  dependencies before linting, testing, and coverage measurement. No manual
  dependency lists required in standard setups.

- *Stable Dependency & Archive Caching*: Caches installed packages and archive
  index metadata (=archive-contents=) across runs using stable dependency
  hashes (extracting =Package-Requires= and manifests rather than hashing source
  code) and weekly rolling epochs. Eliminates repetitive multi-megabyte MELPA
  downloads and slashes warm CI runtimes.

- *Single-Location Dependency & Option Configuration*: If extra dependencies or
  custom paths are needed, they can be declared once at the workflow or job level
  using environment variables (=ELISP_CI_DEPENDENCIES=, =ELISP_CI_LOAD_PATHS=,
  =ELISP_CI_ARCHIVES=, =ELISP_CI_CACHE=) instead of duplicating them across every step.

- *Automatic GPG Keyring & Archive Setup*: Preconfigures GNU ELPA, NonGNU ELPA,
  MELPA, and ELPAish snapshot archives. Automatically fetches and imports the
  ELPAish GPG public keyring for cryptographic signature validation, with
  seamless unsigned archive fallback and cached keyring reuse.

- *Configurable Quality Linters*: Byte-compilation (with warnings-as-errors),
  =checkdoc= docstring linting, =package-lint=, and =relint= with granular
  required/advisory failure gates.

- *Coverage Reporting & UI Summary*: Measures code coverage with =under-cover=
  in SimpleCov, LCOV, Coveralls, or text formats, and renders summary tables
  directly to GitHub Actions Job Summaries (=$GITHUB_STEP_SUMMARY=).

* Specifying Dependencies
:PROPERTIES:
:CUSTOM_ID: specifying-dependencies
:END:

=elisp-ci= supports three dependency resolution strategies (in order of priority):

1. *Step-Level Input* (=with: dependencies: "..."=): Overrides dependencies for
   a specific step. Accepts space/comma-delimited strings or YAML block scalars.
2. *Workflow or Job-Level Environment Variable* (=env: ELISP_CI_DEPENDENCIES: "..."=):
   Declares dependencies *once* for the entire workflow or job without repeating
   them across lint, test, and coverage steps.
3. *Automatic Header Extraction (Default, Zero-Config)*: If no explicit dependencies
   are given, =elisp-ci= automatically inspects =;; Package-Requires:= in all
   =*.el= files, filters out Emacs built-ins, and installs required packages.

#+begin_src yaml
# Example: Setting dependencies and caching once at the job level
jobs:
  test:
    runs-on: ubuntu-latest
    container: silex/emacs:${{ matrix.emacs-version }}-ci
    env:
      ELISP_CI_DEPENDENCIES: "compat transient"
    steps:
      - uses: actions/checkout@v5
      - uses: tychoish/elisp-ci/cache@main
        with:
          emacs-version: ${{ matrix.emacs-version }}
      - uses: tychoish/elisp-ci/lint@main
      - uses: tychoish/elisp-ci@main
      - uses: tychoish/elisp-ci/coverage@main
#+end_src

** Dependency Cache
:PROPERTIES:
:CUSTOM_ID: dependency-cache
:END:

Restores and saves cached Emacs ELPA/MELPA packages, archive metadata, and GPG keyrings.

*Action reference*: =tychoish/elisp-ci/cache@main=

*** Options

| Input           | Default             | Description                                                  |
|-----------------+---------------------+--------------------------------------------------------------|
| =cache=         | ="true"=          | Master switch for caching (true/false, or 'all').            |
| =cache-elpa=    | ="true"=          | Specifically toggle ELPA package and archive cache.          |
| =cache-dir=     | ="~/.emacs.d/elpa"= | Directory for cached packages and metadata.                |
| =cache-key=     | =""=              | Custom cache key salt for manual cache rotation.             |
| =emacs-version= | =""= (detected)   | Emacs version string (e.g. =29.4=, =30.2=).                  |
| =dependencies=  | =""=              | Extra dependencies to include in cache key hash.             |

*** Stable Key Strategy
Unlike naive caches that hash all =**/*.el= files (causing cache misses on every
code edit and thrashing repository cache limits), =tychoish/elisp-ci/cache=
computes cache keys using:
1. *Emacs Version*: Scoped per major/minor release to prevent bytecode incompatibilities.
2. *Dependency Definitions*: Only hashes =Package-Requires:= headers, manifest files
   (=Cask=, =Eldev=, =Eask=, =*-pkg.el=), and explicit input/environment dependencies.
3. *Weekly Rolling Epoch*: Updates rolling MELPA snapshots on a scheduled cadence
   without thrashing on consecutive commits.
4. *Multi-Tier Restore Keys*: Falls back to the latest warm cache on dependency additions,
   so only newly added packages need to be downloaded.

** ELPAish Repository Builder
:PROPERTIES:
:CUSTOM_ID: elpaish-repository-builder
:END:

Builds and packages arbitrary Emacs package archives across snapshot, stable,
and staging streams with static website generation, detached OpenPGP signatures,
and automatic two-layer caching using the ELPAish builder toolkit.

*Action reference*: =tychoish/elisp-ci/elpaish@main=

*** Options

| Input                   | Default       | Description                                                                 |
|-------------------------+---------------+-----------------------------------------------------------------------------|
| =packages-file=         | =packages.el= | Path to package recipe definitions file.                                    |
| =output-dir=            | =public/=     | Directory where the static site and archive streams are written.            |
| =work-dir=              | =repos/=      | Directory where remote Git repositories are cloned and updated.             |
| =streams=               | =all=         | Space-separated list of streams to generate (=all=, or =snapshot stable=). |
| =signing-key=           | =""=          | GPG private key armor for archive signing (omit for unsigned archives).    |
| =gpg-passphrase=        | =""=          | Passphrase for the GPG signing key.                                        |
| =cache=                 | ="true"=      | Enable dependency and Git repository caching.                                |
| =cache-dir=             | =elpa-ci=     | Cache directory for installed ELPA packages and archive metadata.           |
| =cache-repos=           | ="true"=      | Cache the =work-dir= Git clones to eliminate full re-clones between builds.  |
| =preflight=             | ="0"=         | Run preflight quality checks before publishing (=0= or =1=).                |
| =upload-pages-artifact= | ="false"=     | Automatically upload output directory as a GitHub Pages deployment artifact.|

*** GitHub Pages Deployment Example

#+begin_src yaml
- name: Publish ELPA Repository
  uses: tychoish/elisp-ci/elpaish@main
  with:
    packages-file: "packages.el"
    output-dir: "public/"
    signing-key: ${{ secrets.ELPAISH_SIGNING_KEY }}
    gpg-passphrase: ${{ secrets.ELPAISH_GPG_PASSPHRASE }}
    upload-pages-artifact: "true"
#+end_src

** Batch Evaluation Runner
:PROPERTIES:
:CUSTOM_ID: batch-evaluation-runner
:END:

Evaluates arbitrary inline Emacs Lisp expressions or executes script files in batch mode
without shell quoting collisions or container path discrepancies.

*Action reference*: =tychoish/elisp-ci/eval@main=

*** Options

| Input               | Default       | Description                                                                 |
|---------------------+---------------+-----------------------------------------------------------------------------|
| =eval=              | =""=          | Inline Emacs Lisp code to evaluate in batch mode.                           |
| =file=              | =""=          | Path to an Emacs Lisp script to load and execute.                          |
| =load-paths=        | ="."=         | Directories to prepend to =load-path= (space/newline-delimited string).     |
| =action-path=       | =""=          | Project or action root for resolving relative paths and container mounts.   |
| =dependencies=      | =""=          | ELPA packages to install prior to evaluation.                               |
| =archives=          | ="gnu nongnu melpa elpaish"= | Package archives to enable.                                 |
| =cache=             | ="false"=     | Enable dependency caching for installed packages.                           |
| =cache-dir=         | ="~/.emacs.d/elpa"= | Directory for cached packages and metadata.                           |

*** Features
- *Zero Quoting Collisions*: Pass multi-line Elisp expressions using YAML's =|= scalar syntax.
  Bash never interpolates the expressions, so single quotes, double quotes, and complex macros work naturally.
- *Container-Aware Path Helper*: Exposes =(elisp-ci-action-path)= in Lisp code to reliably locate files
  whether running on the bare runner host or inside Docker container mount paths (=/__w/...=).
- *Combined Execution*: If both =file= and =eval= are specified, the script file is loaded first,
  followed by evaluation of the inline expression.

*** Examples

**** Inline Lisp Expression
#+begin_src yaml
- name: Evaluate Elisp
  uses: tychoish/elisp-ci/eval@main
  with:
    load-paths: |
      pkg
      test
    eval: |
      (require 'my-pkg)
      (message "Computed: %s" (my-pkg-calculate 42))
#+end_src

**** Script File Execution
#+begin_src yaml
- name: Run Build Script
  uses: tychoish/elisp-ci/eval@main
  with:
    load-paths: "pkg scripts"
    file: scripts/build.el
#+end_src

**** Container-Aware Root with Action Path
#+begin_src yaml
- name: Bootstrap Action Dependencies
  uses: tychoish/elisp-ci/eval@main
  with:
    action-path: ${{ github.action_path }}
    eval: |
      (let ((root (elisp-ci-action-path)))
        (load (expand-file-name "scripts/bootstrap.el" root) nil nil t))
#+end_src


* Supported Linters & Quality Gates
:PROPERTIES:
:CUSTOM_ID: supported-linters
:END:

The =lint= sub-action supports four integrated analyzers:

1. =byte-compile=: Runs Emacs batch byte-compilation. When =fail-on-warning: true=
   is set, compiler warnings (unresolved variables, obsolete functions,
   missing requires) fail the build.

2. =checkdoc=: Validates standard Emacs Lisp docstring style (sentence casing,
   capitalization of parameter names, header comments).

3. =package-lint=: Validates compliance with ELPA/MELPA packaging standards
   (automatically installed if enabled).

4. =relint=: Scans regular expressions for syntax errors and inefficiencies
   (automatically installed if enabled).

* Example Workflow
:PROPERTIES:
:CUSTOM_ID: example-workflow
:END:

A complete, zero-boilerplate CI matrix workflow with caching, linting, ERT tests, code coverage, and Codecov upload:

#+begin_src yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    runs-on: ubuntu-latest
    container: silex/emacs:${{ matrix.emacs-version }}-ci
    timeout-minutes: 5
    strategy:
      fail-fast: false
      matrix:
        emacs-version:
          - "29.4"
          - "30.2"
          - "31.1"

    steps:
      - uses: actions/checkout@v5

      - name: Cache Emacs Dependencies
        uses: tychoish/elisp-ci/cache@main
        with:
          emacs-version: ${{ matrix.emacs-version }}

      - name: Lint Source Code
        uses: tychoish/elisp-ci/lint@main

      - name: Run ERT Tests
        uses: tychoish/elisp-ci@main

      - name: Measure Code Coverage
        uses: tychoish/elisp-ci/coverage@main
        with:
          report-format: "lcov"
          output-file: "coverage/lcov.info"

      - name: Upload Coverage to Codecov
        uses: codecov/codecov-action@v5
        if: ${{ !cancelled() }}
        with:
          files: coverage/lcov.info
          fail_ci_if_error: false
#+end_src
